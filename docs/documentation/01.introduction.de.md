# Trinity AI Agent Designer

> **Modulare Multi-Agenten-Orchestrierung & Autonome Task Chains**  
> Trinity ist eine Entwicklungs- und Ausführungsplattform für autonome KI-Agenten, bestehend aus einem performanten **Python Flask Backend** und einem reaktiven **Angular Frontend**. Das System ermöglicht das Designen, Verwalten und Ausführen von spezialisierten Agenten, die komplexe mehrstufige Workflows eigenständig planen und abarbeiten.

## Überblick & Architektur

Trinity trennt Programmlogik, Agentenorchestrierung und Benutzeroberfläche strikt in zwei autarke Systeme:

```
                  ┌────────────────────────────────────────┐
                  │       Trinity Angular Frontend         │
                  │   (Chat-UI, Agent Designer, Memory)    │
                  └───────────────────┬────────────────────┘
                                      │
                         REST API / SSE Streams
                                      │
                  ┌───────────────────▼────────────────────┐
                  │        Trinity Flask Backend           │
                  │  ┌──────────────────────────────────┐  │
                  │  │      Agent Orchestrator          │  │
                  │  └─────────────────┬────────────────┘  │
                  │                    │                   │
                  │  ┌─────────────────▼────────────────┐  │
                  │  │     Tool Execution Engine        │  │
                  │  │ (Web, API, File, ODF, Sub-Agents)│  │
                  │  └─────────────────┬────────────────┘  │
                  │                    │                   │
                  │  ┌─────────────────▼────────────────┐  │
                  │  │ Storage (SQLite/MySQL) & Vectors │  │
                  │  └──────────────────────────────────┘  │
                  └───────────────────┬────────────────────┘
                                      │
                     LLM Provider (Gemini / OpenAI)
```

- **Backend (Python / Flask):** Verwaltet Agentendefinitionen, Persistenzschichten via SQLAlchemy (SQLite / MySQL), Wissensdatenbanken und die Ausführungsumgebung für Dateizugriffe und API-Schnittstellen.
- **Frontend (Angular):** Bietet eine intuitive Oberfläche zur Konfiguration von Prompts, Einsicht in historische Task-Verläufe, Dateiverwaltung und Streaming-Interaktion in Echtzeit.

## Kernkonzepte

### 1. Autonome Task Chains
Agenten verharren nicht in reinen Chat-Antworten. Sobald eine Anfrage externe Recherche, Dateimanipulation oder Schnittstellenkommunikation erfordert, generiert der Agent eine strukturierte **Task Chain**. Die Schritte bauen über Referenz-Tokens (z. B. `[STEP_1]`) aufeinander auf und werden deterministisch abgearbeitet.

### 2. Agent Memory (Kontextsteuerung)
Trinity verfügt über eine feingranulare Speicherverwaltung, um Token-Budgets gezielt zu schonen:
- **`memory_enabled`**: Vollständiges Aktivieren/Deaktivieren des Gedächtnisses.
- **`memory_mode`**:
  - `user_only`: Leitet ausschließlich vergangene Nutzerfragen weiter (ideal zur Themeneingrenzung bei minimalem Tokenverbrauch).
  - `all`: Berücksichtigt den gesamten Dialogverlauf inklusive aller Agentenantworten.
- **`memory_limit_type` & `memory_message_count`**: Begrenzung auf die letzten $N$ Nachrichten oder unbegrenzte Historie (`all`).

### 3. Sub-Agent Delegation
Komplexe Aufgaben können an Sub-Agenten delegiert werden (`message_agent`). Ein Hauptagent kann spezialisierte Agenten für Code-Reviews, juristische Analysen oder Übersetzungen instruieren. Eine integrierte Rekursionssperre (`MAX_SUBAGENT_CALL_DEPTH = 3`) verhindert Endlosschleifen.

### 4. Knowledge Base & Datasources
Dateien (PDFs, Markdown, Textdokumente, Tabellen) können direkt an Agenten gekoppelt werden. Bei Anfragen nutzt der Agent diese Dokumente als priorisierte Wissensquelle, bevor externe Werkzeuge bemüht werden.

## Integrierte Werkzeuge (Tool Ecosystem)

Trinity stellt den Agenten eine breite Palette an Werkzeugen zur Verfügung:

| Werkzeug | Kategorie | Beschreibung |
| :--- | :--- | :--- |
| `fetch_url` | Web & Daten | Ruft Volltexte aus Webseiten oder Online-Dokumenten ab. |
| `web_search` | Recherche | Live-Websuche via **Tavily API** oder Zero-Config **DuckDuckGo** Fallback. |
| `call_api` | Schnittstellen | Führt HTTP-Operationen (GET, POST, PUT, DELETE) gegen REST-APIs aus. |
| `read_file` | Workspace | Liest Dateien oder listet Verzeichnisse im isolierten Session-Workspace auf. |
| `write_file` | Workspace | Schreibt strukturierte Inhalte, Logs oder Code in Dateien. |
| `manage_odf` | Dokumente | Erstellt, liest und erweitert `.odt` (Text), `.ods` (Tabellen) und `.odp` (Präsentationen). |
| `generate_image` | Medien | Generiert Bilder via Gemini oder DALL-E anhand von Prompts. |
| `send_email` | Kommunikation | Versendet formatierte E-Mails via SMTP oder lokale MTAs. |
| `message_agent` | Orchestrierung | Übergibt Teilaufgaben an andere registrierte Trinity-Agenten. |
| `message_llm` | Transformation | Zwischenschritt zur Synthese, Übersetzung oder Extraktion von Daten. |

## Systemvoraussetzungen & Stack

- **Laufzeitumgebung:** Python 3.10+
- **Datenbank:** SQLite (Standard) oder MySQL 8.x
- **LLM-Integration:** Google Gemini (`google-genai`), OpenAI (`openai`)
- **Frontend:** Node.js 18+, Angular CLI
- **Protokolle:** REST JSON API, Server-Sent Events (SSE)

## Schnellstart

### 1. Backend einrichten

```bash
# 1. Repository klonen
git clone https://github.com/negsi/trinity-flask.git
cd trinity-flask

# 2. Virtuelle Umgebung erstellen und aktivieren
python3 -m venv venv
source venv/bin/activate  # Unter Windows: venv\Scripts\activate

# 3. Abhängigkeiten installieren
pip install -r requirements.txt
pip install google-genai  # oder pip install openai

# 4. Umgebungsvariablen konfigurieren
cp .env.template .env

# 5. Datenbank initialisieren und migrieren
flask db upgrade

# 6. Backend-Server starten
python run_app.py
```

### 2. Frontend anbinden

Das Frontend verbindet sich standardmäßig mit dem Backend unter `http://127.0.0.1:5000`:

```bash
git clone https://github.com/negsi/trinity-angular.git
cd trinity-angular
npm install
ng serve
```

Die Benutzeroberfläche ist anschließend im Browser unter `http://localhost:4200` erreichbar.

## API & Kommunikationsprotokoll

Das Backend stellt unter `/api/v1` eine REST-Schnittstelle bereit.

### Wichtigste Endpunkte

- `GET /api/v1/agents` – Ruft alle registrierten Agenten ab.
- `POST /api/v1/agents` – Erstellt einen neuen Agenten samt Memory-Konfiguration.
- `POST /api/v1/agents/<agent_id>/datasources` – Lädt Dokumente in die Knowledge Base hoch.
- `POST /api/v1/agents/<agent_id>/stream` – Initiiert den SSE-Stream für Prompts und Task-Chain-Events.

```bash
# Beispiel: Agenten per REST anlegen
curl -X POST http://127.0.0.1:5000/api/v1/agents \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Research Analyst",
    "description": "Spezialist für Marktanalysen",
    "system_prompt": "Führe tiefgehende Marktanalysen durch. Nutze Websuchen gezielt.",
    "memory_enabled": true,
    "memory_mode": "user_only",
    "memory_limit_type": "message_count",
    "memory_message_count": 10
  }'
```
