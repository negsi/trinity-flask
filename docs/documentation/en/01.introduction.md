# Trinity AI Agent Designer

> **Modular Multi-Agent Orchestration & Autonomous Task Chains**  
> Trinity is a development and execution platform for autonomous AI agents, consisting of a high-performance **Python Flask backend** and a reactive **Angular frontend**. The system enables designing, managing, and executing specialized agents that autonomously plan and process complex multi-step workflows.

## Overview & Architecture

Trinity strictly separates program logic, agent orchestration, and user interface into two autonomous systems:

```
                  ┌────────────────────────────────────────┐
                  │       Trinity Angular Frontend         │
                  │   (Chat-UI, Agent Designer, Memory)    │
                  └───────────────────┬────────────────────┘
                                      │
                         REST API / SSE Streams
                                      │
                  ┌───────────────────▼────────────────────┐
                  │        Trinity Flask Backend           │
                  │  ┌──────────────────────────────────┐  │
                  │  │      Agent Orchestrator          │  │
                  │  └─────────────────┬────────────────┘  │
                  │                    │                   │
                  │  ┌─────────────────▼────────────────┐  │
                  │  │     Tool Execution Engine        │  │
                  │  │ (Web, API, File, ODF, Sub-Agents)│  │
                  │  └─────────────────┬────────────────┘  │
                  │                    │                   │
                  │  ┌─────────────────▼────────────────┐  │
                  │  │ Storage (SQLite/MySQL) & Vectors │  │
                  │  └──────────────────────────────────┘  │
                  └───────────────────┬────────────────────┘
                                      │
                     LLM Provider (Gemini / OpenAI)
```

- **Backend (Python / Flask):** Manages agent definitions, persistence layers via SQLAlchemy (SQLite / MySQL), knowledge bases, and the execution environment for file access and API endpoints.
- **Frontend (Angular):** Provides an intuitive interface for configuring prompts, inspecting historical task execution logs, managing files, and real-time streaming interactions.

## Core Concepts

### 1. Autonomous Task Chains
Agents do not stop at simple chat responses. As soon as a request requires external research, file manipulation, or interface communication, the agent generates a structured **Task Chain**. The steps build upon each other using reference tokens (e.g., `[STEP_1]`) and are processed deterministically.

### 2. Agent Memory (Context Control)
Trinity features granular memory management to selectively conserve token budgets:
- **`memory_enabled`**: Completely enables or disables memory.
- **`memory_mode`**:
  - `user_only`: Forwards exclusively past user queries (ideal for scope limitation with minimal token consumption).
  - `all`: Considers the entire dialogue history including all agent responses.
- **`memory_limit_type` & `memory_message_count`**: Limits context to the last $N$ messages or keeps an unlimited history (`all`).

### 3. Sub-Agent Delegation
Complex tasks can be delegated to sub-agents (`message_agent`). A primary agent can instruct specialized agents for code reviews, legal analysis, or translations. An integrated recursion lock (`MAX_SUBAGENT_CALL_DEPTH = 3`) prevents infinite loops.

### 4. Knowledge Base & Datasources
Files (PDFs, Markdown, text documents, spreadsheets) can be directly linked to agents. When processing requests, the agent utilizes these documents as a prioritized source of knowledge before resorting to external tools.

## Integrated Tools (Tool Ecosystem)

Trinity provides agents with a wide array of tools:

| Tool | Category | Description |
| :--- | :--- | :--- |
| `fetch_url` | Web & Data | Fetches full texts from web pages or online documents. |
| `web_search` | Research | Live web search via **Tavily API** or zero-config **DuckDuckGo** fallback. |
| `call_api` | Interfaces | Executes HTTP operations (GET, POST, PUT, DELETE) against REST APIs. |
| `read_file` | Workspace | Reads files or lists directories in the isolated session workspace. |
| `write_file` | Workspace | Writes structured content, logs, or code to files. |
| `manage_odf` | Documents | Creates, reads, and expands `.odt` (text), `.ods` (spreadsheets), and `.odp` (presentations). |
| `generate_image` | Media | Generates images via Gemini or DALL-E based on prompts. |
| `send_email` | Communication | Sends formatted emails via SMTP or local MTAs. |
| `message_agent` | Orchestration | Hands over sub-tasks to other registered Trinity agents. |
| `message_llm` | Transformation | Intermediate step for synthesizing, translating, or extracting data. |

## System Requirements & Stack

- **Runtime Environment:** Python 3.10+
- **Database:** SQLite (Default) or MySQL 8.x
- **LLM Integration:** Google Gemini (`google-genai`), OpenAI (`openai`)
- **Frontend:** Node.js 18+, Angular CLI
- **Protocols:** REST JSON API, Server-Sent Events (SSE)

## Quick Start

### 1. Set Up Backend

```bash
# 1. Clone repository
git clone https://github.com/negsi/trinity-flask.git
cd trinity-flask

# 2. Create and activate a virtual environment
python3 -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate

# 3. Install dependencies
pip install -r requirements.txt
pip install google-genai  # or pip install openai

# 4. Configure environment variables
cp .env.template .env

# 5. Initialize and migrate database
flask db upgrade

# 6. Start the backend server
python run_app.py
```

### 2. Connect Frontend

By default, the frontend connects to the backend at `http://127.0.0.1:5000`:

```bash
git clone https://github.com/negsi/trinity-angular.git
cd trinity-angular
npm install
ng serve
```

The user interface can then be accessed in the browser at `http://localhost:4200`.

## API & Communication Protocol

The backend exposes a REST interface under `/api/v1`.

### Key Endpoints

- `GET /api/v1/agents` – Retrieves all registered agents.
- `POST /api/v1/agents` – Creates a new agent including memory configuration.
- `POST /api/v1/agents/<agent_id>/datasources` – Uploads documents to the knowledge base.
- `POST /api/v1/agents/<agent_id>/stream` – Initiates the SSE stream for prompts and task chain events.

```bash
# Example: Create an agent via REST
curl -X POST http://127.0.0.1:5000/api/v1/agents \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Research Analyst",
    "description": "Specialist for market analyses",
    "system_prompt": "Conduct in-depth market analyses. Use web searches strategically.",
    "memory_enabled": true,
    "memory_mode": "user_only",
    "memory_limit_type": "message_count",
    "memory_message_count": 10
  }'
```
