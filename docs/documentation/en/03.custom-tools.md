## 1. Architecture & Tool Lifecycle

A tool in Trinity is a stateless or stateful Python function invoked via the `ToolRegistry` service:

```
┌────────────────────────────────────────────────────────┐
│               LLM generates Task Chain                 │
│         { "tool": "custom_tool", "parameters": {...} } │
└───────────────────────────┬────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────┐
│            AgentOrchestrator / TaskEngine              │
│       • Resolves tokens ([STEP_1], REF:PAYLOAD_*)      │
│       • Injects session metadata (conversation_id)     │
└───────────────────────────┬────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────┐
│                     ToolRegistry                       │
│       • Validates callable availability                │
│       • Forwards storage, mail, or DB services         │
└───────────────────────────┬────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────┐
│                 Custom Tool Function                   │
│           def custom_tool(*args, **kwargs)             │
└────────────────────────────────────────────────────────┘
```

Every tool automatically benefits from:
- **Sandbox Isolation:** Read and write operations are restricted to the conversation directory by default (`instance/conversations/<conversation_id>/`).
- **Token Resolution:** Placeholders from previous steps (like `[STEP_1]`) are automatically replaced with the respective step's output prior to function execution.
- **Content Payloads:** Large texts or scripts outsourced via `REF:PAYLOAD_STEP_N` arrive unmasked in the parameter.

## 2. Anatomy of a Tool Function

### Signature & Sandboxing

A clean tool function should adhere to the following conventions at minimum:
- Use **strict typing** (Type Hints) according to Python 3.10+.
- Capture optional framework metadata via `**kwargs` (`conversation_id`, `base_dir`, etc.).
- Paths must **never** be accepted unvalidated from user inputs.

```python
from pathlib import Path
from typing import Any
import logging

logger = logging.getLogger(__name__)

def my_custom_tool(
    param_a: str,
    param_b: int = 10,
    conversation_id: str | None = None,
    base_dir: str | Path | None = None,
    **kwargs: Any,
) -> dict[str, Any] | str:
    """Short description for logging and introspection."""
    try:
        # Actual logic here...
        return {"status": "success", "result": f"Processed: {param_a}"}
    except Exception as exc:
        logger.error(f"Error executing my_custom_tool: {exc}", exc_info=True)
        return {"error": str(exc)}
```

### Return Values & Error Handling

- **Return Type:** Return structured dictionaries (`dict[str, Any]`) or clean plaintext strings.
- **No Uncaught Exceptions:** Tools should deterministically return `{"error": "Error message"}` or an understandable error description as a string so that the agent can respond within a task chain and initiate corrective steps.

## 3. Step-by-Step Guide: Tool Registration

### Step 1: Create Python Module

Place your tools in the `app/services/tools/` directory. For example, create the file `app/services/tools/custom_network_tools.py`:

```python
# app/services/tools/custom_network_tools.py
import socket
from typing import Any

def dns_lookup(hostname: str, **kwargs: Any) -> dict[str, Any]:
    """Resolves a hostname into its IPv4 addresses."""
    try:
        clean_host = hostname.strip().replace("http://", "").replace("https://", "").split("/")[0]
        _, _, ip_addresses = socket.gethostbyname_ex(clean_host)
        return {
            "hostname": clean_host,
            "ip_addresses": ip_addresses
        }
    except socket.gaierror as err:
        return {"error": f"DNS resolution failed: {err}"}
```

### Step 2: Registration in ToolRegistry

Open `app/services/tools/registry.py` and bind your new function.

#### Variant A: Permanently configured in `get_tools()` (Standard for Core Tools)

```python
# app/services/tools/registry.py
from app.services.tools.custom_network_tools import dns_lookup

class ToolRegistry:
    # ...
    def get_tools(self) -> dict[str, Callable[..., Any]]:
        base_tools: dict[str, Callable[..., Any]] = {
            "fetch_url": fetch_url,
            "web_search": web_search,
            "message_llm": message_llm,
            "message_agent": self.message_agent,
            "call_api": call_api,
            "write_file": self.write_file,
            "read_file": self.read_file,
            "send_email": self.send_email,
            "generate_image": self.generate_image,
            "manage_odf": self.manage_odf,
            # New Custom Tool:
            "dns_lookup": dns_lookup,
        }
        base_tools.update(self._custom_tools)
        return base_tools
```

#### Variant B: Dynamic Registration at Runtime

If you use a plugin system or load tools modularly:

```python
tool_registry.register_tool("dns_lookup", dns_lookup)
```

### Step 3: Adjust Dependency Injection in Container

If your tool requires access to infrastructure services (e.g., `FileStorageService` or `DatabaseSession`), create a wrapper method on `ToolRegistry` and inject the dependency via `app/containers.py`:

```python
# app/services/tools/registry.py
class ToolRegistry:
    def __init__(
        self,
        file_storage_service: FileStorageService,
        email_service: EmailService | None = None,
        # Additional dependencies ...
    ) -> None:
        self.file_storage_service = file_storage_service
        # ...
```

### Step 4: Define Tool in the System Prompt

So the LLM knows **that** the tool exists and **how** it must be invoked, add it to the base prompt (`app/templates/prompts/base_agent.prompt.md`) or the individual agent's `system_prompt`:

```markdown
11. `dns_lookup`: Performs a DNS name resolution for a domain.
    - **Parameters:** `hostname` (string, required: domain or hostname without protocol).
    - **Example:** `{"hostname": "example.org"}`
```

## 4. Practical Examples

### Example 1: DNS & Domain Lookup Tool (`dns_lookup`)

Enables security and network agents to query DNS records.

```python
# app/services/tools/network_tools.py
import socket
from typing import Any

def dns_lookup(hostname: str, **kwargs: Any) -> dict[str, Any]:
    """
    Performs a forward DNS lookup.

    Args:
        hostname: Domain name (e.g. 'github.com')
    """
    if not hostname:
        return {"error": "Parameter 'hostname' must not be empty."}

    # Cleanup: Remove protocol prefixes and paths
    domain = hostname.strip().lower()
    for prefix in ["https://", "http://"]:
        if domain.startswith(prefix):
            domain = domain[len(prefix):]
    domain = domain.split("/")[0].split(":")[0]

    try:
        primary_name, aliases, ip_list = socket.gethostbyname_ex(domain)
        return {
            "query": hostname,
            "canonical_name": primary_name,
            "aliases": aliases,
            "ip_addresses": ip_list,
            "status": "success",
        }
    except socket.gaierror as e:
        return {
            "query": hostname,
            "status": "failed",
            "error": f"DNS lookup failed: {e.strerror} (Code: {e.errno})"
        }
```

### Example 2: Python Code Linter & AST Checker (`lint_python_code`)

Validates Python files or code snippets in the conversation directory for syntax errors before they are executed or committed.

```python
# app/services/tools/dev_tools.py
import ast
from pathlib import Path
from typing import Any

def lint_python_code(
    file_path: str | None = None,
    code: str | None = None,
    conversation_id: str | None = None,
    base_dir: str | Path | None = None,
    **kwargs: Any,
) -> dict[str, Any]:
    """
    Validates Python source code for syntax errors via AST parsing.

    Args:
        file_path: Relative path to the file in the workspace (optional).
        code: Direct code string to check (optional).
    """
    target_code = code

    # If file_path is provided, read its content from the secure workspace
    if file_path:
        if not base_dir or not conversation_id:
            return {"error": "Workspace context (base_dir, conversation_id) is missing."}

        safe_path = Path(base_dir) / conversation_id / Path(file_path).name
        if not safe_path.is_file():
            return {"error": f"File '{file_path}' was not found in the workspace."}

        try:
            target_code = safe_path.read_text(encoding="utf-8")
        except Exception as err:
            return {"error": f"Error reading file: {err}"}

    if not target_code:
        return {"error": "Neither 'code' nor 'file_path' was provided."}

    try:
        tree = ast.parse(target_code)
        
        # Extract basic AST statistics
        function_count = sum(isinstance(node, ast.FunctionDef) for node in ast.walk(tree))
        class_count = sum(isinstance(node, ast.ClassDef) for node in ast.walk(tree))

        return {
            "valid": True,
            "message": "Syntax is clean.",
            "metrics": {
                "functions": function_count,
                "classes": class_count,
                "lines": len(target_code.splitlines())
            }
        }
    except SyntaxError as syntax_err:
        return {
            "valid": False,
            "error": "SyntaxError",
            "message": syntax_err.msg,
            "line": syntax_err.lineno,
            "offset": syntax_err.offset,
            "text": syntax_err.text.strip() if syntax_err.text else None,
        }
```

### Example 3: SQLite Query & Table Inspector (`query_sqlite`)

Allows data science agents to execute read-only queries against local SQLite databases within the workspace.

```python
# app/services/tools/db_tools.py
import sqlite3
from pathlib import Path
from typing import Any

def query_sqlite(
    db_filename: str,
    sql_query: str,
    max_rows: int = 50,
    conversation_id: str | None = None,
    base_dir: str | Path | None = None,
    **kwargs: Any,
) -> dict[str, Any]:
    """
    Executes read-only SELECT queries on a workspace SQLite database.

    Args:
        db_filename: Name of the SQLite file (e.g. 'data.db').
        sql_query: The SELECT statement to execute.
        max_rows: Maximum result rows (default: 50).
    """
    if not sql_query.strip().lower().startswith("select"):
        return {"error": "Security restriction: Only 'SELECT' queries are permitted."}

    if not base_dir or not conversation_id:
        return {"error": "Workspace context is missing."}

    # Secure sandbox path
    db_path = (Path(base_dir) / conversation_id / Path(db_filename).name).resolve()
    if not db_path.is_file():
        return {"error": f"Database file '{db_filename}' does not exist in the workspace."}

    try:
        # Open in read-only URI mode
        uri = f"file:{db_path.as_posix()}?mode=ro"
        with sqlite3.connect(uri, uri=True, timeout=5.0) as conn:
            conn.row_factory = sqlite3.Row
            cursor = conn.cursor()
            cursor.execute(sql_query)
            
            columns = [col[0] for col in cursor.description] if cursor.description else []
            rows = [dict(row) for row in cursor.fetchmany(max_rows)]

            return {
                "status": "success",
                "row_count": len(rows),
                "columns": columns,
                "data": rows,
                "truncated": len(rows) == max_rows
            }
    except sqlite3.Error as db_err:
        return {"status": "error", "error": f"SQLite error: {db_err}"}
```

## 5. Best Practices & Security Guidelines

1. **Prevent Path Traversal:**  
   Never use unvalidated relative paths like `../../etc/passwd`. Always use `Path(filename).name` to prevent directory navigation, or validate that the resolved target path (`.resolve()`) lies strictly within `Path(base_dir) / conversation_id`.

2. **No Destructive Commands Without Safeguards:**  
   Operations like `eval()`, `exec()`, or shell subprocesses (`subprocess.run(..., shell=True)`) should be avoided. If code must be executed, use AST checks or dedicated containers/sandboxes.

3. **Set Timeouts:**  
   Network calls (`requests`, `socket`, APIs) and database accesses must always be provided with an explicit `timeout` (e.g., `timeout=10`) so that blocked sockets do not stall the worker thread of the Flask backend.

4. **Compact Outputs for the LLM:**  
   Agents process tool outputs in the next step via `message_llm`. Huge data structures (e.g., 10,000 table rows) exceed the token window. Always limit lists using parameters like `max_results` or `max_rows`.
